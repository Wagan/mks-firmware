# REPORT — Сырой съём полного CIR по раннему событию (CMD_CIR_RAW_ARM / CONTENT=5)

**Автор:** Vagan Sarukhanov
**Дата:** 2026-07-26
**Тип:** реализация (эксперимент)
**Задание:** `docs/TASK_raw_cir_monitor.md`
**Основание:** `docs/RECON_raw_cir_monitor.md` (разведка закрыта)
**Проект:** mks-firmware (МКС, STM32F411 + 2× DWM1000)

> **Классификация.** Временный эксперимент для проверки гипотез будущего 5-канального
> обнаружителя (HANDOFF §15.3), пока его плата не готова. **НЕ фронт МКС, НЕ функция
> продукта.** HANDOFF §11 п.20 и §15.3 в силе.

> **На железе НЕ проверялось.** Сборка/прошивка/замеры — за владельцем (правило
> задания). Ниже — что реализовано и как включать; корректность на плате устанавливает
> замер (см. раздел «Что измерить»).

---

## 1. Что реализовано (кратко)

Одиночный («по запросу») съём **всего** аккумулятора CIR (992/1016 отсчётов) по
**раннему** событию приёма — `RXSFDD`/`RXPHE`/`RXFCE`, **до** зачёта кадра (RXFCG).
Захватывает в т.ч. кадры, провалившиеся на PHR/CRC (главная цель эксперимента). Полный
CIR уходит на хост **одним** потоковым кадром нового типа `CONTENT=5`.

Всё новое — под compile-time флагом `RAW_CIR_MONITOR` (по умолчанию **закомментирован**).
При выключенном флаге прошивка совпадает с текущей (см. раздел 6).

---

## 2. Как включать

В `App/board/board_config.h` (секция `BOARD_MKS`) раскомментировать:

```c
#define RAW_CIR_MONITOR
```

Пересобрать. Появляются: команда `CMD_CIR_RAW_ARM` (0x43) и потоковый кадр `CONTENT=5`.
SPI **не трогается** — остаётся slow (1.125 МГц, ~29 мс на съём; правило 4 задания:
`set_fast` — отдельная правка с отдельным регрессом, `NOTE_spi_set_fast_unused.md`).

## 4. Логика

### Команда `CMD_CIR_RAW_ARM` (0x43)
Params нет, DATA нет. Взводит **одиночный** съём. Требует активного приёма
(`rx_active` = после `RX_START`) — иначе `RADIO_ERROR`. `OK` = взведено. Взвод и сам
съём разнесены: команда только ставит флаг, съём делает `PROTOCOL_PollRadio`.
`protocol.c` → `HandleCIR_RAW_ARM`.

### Триггер (в `PROTOCOL_PollRadio`, `protocol.c`)
Расширен существующий опрос `SYS_STATUS` (не параллельный). Вставлен **до** штатных
веток RXFCG/ошибок, поэтому съём аккумулятора идёт **до** любых `dwt_rxenable`/`rxreset`
(Б4). Флаги RXFCG/ошибок здесь **не снимаются** — их обрабатывают штатные ветки ниже
(поведение прежнее). Приоритет тегирования события:

1. `RXPHE` (кадр не прошёл PHR) — `event=2`
2. `RXFCE` (кадр не прошёл CRC) — `event=3`
3. `RXSFDD` (накопление завершено, Б2; ловит и хорошие кадры для сверки формы) — `event=1`
4. `RXPTO` — **не триггер** (детекта преамбулы не было → CIR не наполнена, Б1);
   инкремент счётчика `raw_cir_nosignal` (виден по SWD) + снятие флага.

После съёма взвод снимается (одноразовый). Индекс first path из LDE **не используется**
(при `RXSFDD` не готов — LDE стартует по RXPHD; съём с offset 0 в нём не нуждается).

### Буфер и съём
Отдельный `static uint8_t raw_cir_buf[1 + 1016*4]` (4065 Б) — `cir_snap` (252 Б) **не
трогается**, `GET_CIR`/`CONTENT=1` работают как раньше. Съём:
`dwt_readaccdata(raw_cir_buf, N*4+1, 0)`, `N` = 1016 (PRF64) / 992 (PRF16) по фактической
конфигурации `dw_dev_state[DW_RX_LISTEN_DEV].prf`; первый (dummy) байт отбрасывается при
отправке. Время `dwt_readaccdata` замеряется `HAL_GetTick` → поле `read_ms` в кадре.
`protocol.c` → `PROTOCOL_CaptureRawCIR`.

### Режим — по запросу, НЕ непрерывный
Съём 4066 Б при slow SPI ~29 мс, приёмник всё это время выключен. Непрерывный полный
съём сделал бы плату слепой между кадрами и обесценил замер — поэтому одиночный
(авто-разоружение). Зафиксировано комментарием в коде.

### Отправка
Отдельная большая `static` буфер-переменная (~4088 Б, не трогает `frame[320]` потока).
`CDC_Transmit_FS` отдаёт указатель напрямую (не копирует в 2048-буфер) — большой кадр
допустим. При CDC BUSY кадр **не теряется**: `DROPPED++`, снимок держится, повтор на
следующем `PollRadio`. `protocol.c` → `PROTOCOL_SendRawCirFrame`.

## 5. Раскладка кадра на проводе (для хост-скрипта архитектора)

Каркас — тот же потоковый формат, что `mks_stream.py` уже разбирает, новый только
`CONTENT=5`:

```
SMARK(0xDE 0xCA) | LEN16(u16 LE) | SEQ(u16 LE) | DROPPED(u16 LE) | CONTENT=5(u8) | PAYLOAD | CRC8
```

- `LEN16` = число байт после LEN16 и до CRC (= SEQ+DROPPED+CONTENT+PAYLOAD).
- `CRC8` — полином `0x07`, по `[LEN16 .. конец PAYLOAD)` (SMARK **не** входит).

**PAYLOAD (все многобайтовые — little-endian):**

| Смещение | Поле | Тип | Смысл |
|---|---|---|---|
| 0 | `event` | u8 | 1=RXSFDD, 2=RXPHE, 3=RXFCE |
| 1 | `prf` | u8 | 16 или 64 |
| 2..3 | `read_ms` | u16 | время `dwt_readaccdata`, мс |
| 4..5 | `sample_count` | u16 | 1016 (PRF64) или 992 (PRF16) |
| 6.. | `I/Q` | int16×2×`sample_count` | сырой CIR (I1,Q1,I2,Q2,…), dummy уже отброшен |

PAYLOAD = `6 + sample_count*4` (до `4070` Б). `SEQ`/`DROPPED` — общие со стримом.

**Порядок работы хоста:** `INIT` → `SET_PHY_CONFIG` → `RX_START` → `CMD_CIR_RAW_ARM (0x43)`
→ ждать один кадр `SMARK 0xDECA` с `CONTENT=5` → разобрать по таблице. Повторный съём —
снова `CMD_CIR_RAW_ARM`. (Стример `SET_STREAM_MODE` для сырого съёма **не** используется.)

## 6. Байт-в-байт при выключенном `#define`

**Гарантируется структурно** (сборку/сравнение бинаря не делали — правило задания):

- **Весь** новый код `protocol.c` (состояние, 3 функции, триггер-блок в `PollRadio`,
  регистрация, сбросы в `PROTOCOL_Init`/INIT) — внутри `#ifdef RAW_CIR_MONITOR`.
  При выключенном флаге препроцессор их удаляет → ни одного нового оператора, ни байта
  `.bss`, ни изменения `PollRadio`/`INIT`.
- Единственное безусловное изменение — константа `CMD_CIR_RAW_ARM = 0x43` в enum
  `CommandID` (`protocol.h`). Неиспользуемая enum-константа **не порождает кода** →
  на бинарь не влияет.
- `board_config.h`: строка `#define` **закомментирована** + комментарий → на
  компиляцию не влияет.

Итог: при закомментированном `RAW_CIR_MONITOR` бинарь идентичен состоянию до этой
правки. **Рекомендация владельцу:** подтвердить сравнением `.bin`/`.map` до/после при
первой пересборке.

## 7. Что эксперимент должен измерить (как реализация это позволяет)

Ссылки — ВЫВОД п.3 разведки. Реализация даёт снять все четыре:

1. **Годна ли CIR по RXSFDD и по RXPHE/RXFCE.** Поле `event` в кадре помечает источник;
   хост сравнивает форму полного CIR (`CONTENT=5`) с окном из `GET_CIR`/`CONTENT=1` на
   том же линке — различим ли первый путь, физичны ли амплитуды. `RXSFDD` ловит и
   хорошие кадры → прямая сверка «полный сырой» vs «окно RXFCG».
2. **Нужен ли AMCE (bit17) на полных 1016 отсчётах.** Vendor `READ_ACC_ON` байт 2 не
   трогает (Б3, гипотеза); на окне 63 отсч. мусора нет. `CONTENT=5` отдаёт весь буфер →
   хост смотрит хвост (последние отсчёты) на мусор/обрыв.
3. **Разрушающее ли чтение ACC_MEM.** Два `CMD_CIR_RAW_ARM` подряд по одному и тому же
   принятому кадру (без нового приёма между ними) — сравнить содержимое. (Прим.: между
   двумя взводами приёмник перевзводится, поэтому чистый тест «то же содержимое» требует
   аккуратности — при необходимости добавить под тем же `#define` вариант «двойное
   чтение в одном съёме»; пока не делал, чтобы не разрастаться сверх задания.)
4. **Реальное время `dwt_readaccdata` 4066 Б.** Поле `read_ms` в каждом кадре
   (`HAL_GetTick`, 1 мс; для ~29 мс достаточно). Точнее — DWT cycle counter, если
   понадобится (не включал: требует инициализации, вне задания).

Пункты 1 и 2 — прямые вопросы к железу будущего макета, и есть главная ценность.

## 8. Ограничения и заметки

- **SPI slow (1.125 МГц) намеренно** — правило 4 задания. ~35 съёмов/с максимум; для
  одиночного эксперимента достаточно.
- **RXPTO-счётчик** (`raw_cir_nosignal`) виден только по SWD; на провод пока не выводится
  (можно добавить в будущем отдельным полем/командой, если понадобится хосту).
- **Кадр `CONTENT=5` ~4 КБ одной USB-передачей** — по коду допустимо (`CDC_Transmit_FS`
  не копирует), но на железе не гонялось; возможные краевые эффекты USB (ZLP на кратных
  64 Б) — предмет замера.
- **`GET_CIR` (0x41) и `CONTENT=1`** (усечённое окно вокруг FP) — не затронуты.
