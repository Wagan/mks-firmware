ШАГ 2 — ПРОЦЕДУРА ОДНОГО ОТСЧЁТА

Последовательность взять ЦЕЛИКОМ из UM §7.2.36.2 и привести её в отчёте
по шагам со ссылкой. По отчёту разведки она включает снятие DIS_AM в 0,
включение приёмника, паузу 32 мкс, установку DIS_AM в 1, чтение AGC_STAT1 и
выключение приёмника — но полный и точный список шагов должен прийти из UM,
не отсюда.

Обязательное восстановление состояния: по завершении процедуры DIS_AM вернуть
в сбросовое значение 1, приёмник оставить выключенным. Плата после команды
должна быть в том же состоянии регистра, что и до неё.

Пауза 32 мкс: найти в существующем коде микросекундный источник задержки
(счётчик циклов, аппаратный таймер, откалиброванный цикл). HAL_Delay не
использовать — он миллисекундный. Если микросекундного источника в коде нет —
СТОП и вопрос, не изобретать свой.

Доступ к регистрам — только через существующие функции драйвера и константы
из deca_regs.h, по образцам, приведённым в разведке. Адреса и маски числом
в код не писать.

Размещение: отдельной функцией в App/protocol/. Если считаешь, что чище
завести новый файл модуля — напиши это в отчёте как предложение, но молча
новых файлов не создавай.


ШАГ 3 — КОМАНДА

Код команды — 0x44 (по разведке свободен; перепроверь по protocol.h перед
использованием).

Запрос: один параметр N — число отсчётов, u8.

Ответ: N отсчётов подряд, каждый по 3 байта — младшие 24 бита AGC_STAT1 как
есть, порядок байт как у остального протокола. Сырое значение, без распаковки
полей и без вычислений на плате: распаковкой и статистикой занимается хост.
Отсюда предел N — он определяется максимальным размером DATA; вычисли его по
PROTOCOL_SPEC и проверь N на входе, вернув ошибку при превышении.

Предусловие: rx_active != 0 → вернуть ошибку. Код ошибки взять из
существующего перечня статусов протокола, новых не заводить.

Цикл: процедура шага 2 повторяется для каждого из N отсчётов целиком, включая
включение и выключение приёмника. Отсчёты не должны зависеть друг от друга.


ШАГ 4 — ДОКУМЕНТ ПРОТОКОЛА

Зарегистрировать команду в PROTOCOL_SPEC новой версией документа: код, формат
запроса и ответа, предусловие по rx_active, и явная пометка, что команда
существует только в сборке с этим флагом. Регистрация обязательна даже при
том, что фича под флагом — иначе номер позже уйдёт под продуктовую команду и
совпадёт с экспериментальной сборкой.


ШАГ 5 — СБОРКА С ВКЛЮЧЁННЫМ ФЛАГОМ
