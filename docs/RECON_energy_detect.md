## ФАКТЫ — ЧАСТЬ А (DW1000 UM v2.17)

### А1. АРУ/AGC — момент и условия обновления; связь с RSSI §4.7

- **RSSI §4.7 НЕ использует поле усиления AGC.** Формула §4.7.2 (печ.45/PDF46): `RX_LEVEL`
  считается из `CIR_PWR` (рег.0x12) и `RXPACC` (рег.0x10) + константа A (113.77@16МГц /
  121.74@64МГц). Отдельного регистра «RX_LEVEL» нет; «RX LEVEL» — только подпись оси Figure 22.
  ⇒ величина RSSI **привязана к принятому кадру** (RXPACC — счётчик накопления преамбулы).
- **Отдельная функция AGC — измеряется БЕЗ кадра.** Sub-Register 0x23:02 AGC_CTRL1, бит `DIS_AM`
  (§7.2.36.2, печ.122/PDF123): *«When DIS_AM bit is clear and the receiver is enabled the AGC
  will settle on an estimate of the background energy level and the result will be available via
  the EDG1 and EDV2 values in Sub-Register 0x23:1E - AGC_STAT1.»* Процедура (там же): включить RX,
  ждать 32 µs, поставить DIS_AM=1 (заморозить), прочитать EDG1/EDV2, посчитать энергию шума.
- **Вывод А1:** отдельно читаемого per-frame «gain» в документе нет, и в RSSI §4.7 он не входит
  (RSSI сам по кадру). Но есть **AGC-измерение фона `EDG1/EDV2` (0x23:1E)**, которое **осмысленно
  именно ВНЕ кадра** — «settle on background energy level» при включённом RX без детекта преамбулы.
  EDG1 — «5-bit gain value relates to input noise power measurement» (печ.125/PDF126).

### А2. Оценка шума (STD_NOISE)

- `STD_NOISE` (рег.0x12, §7.2.20, печ.98/PDF99): *«standard deviation of the noise level seen
  **during the LDE algorithm's analysis of the accumulator data**.»* Поля рег.0x12 *«updated when
  the LDE execution has completed successfully (when the LDEDONE status bit is set)».*
- **Вывод А2:** STD_NOISE действителен **только после успешного LDE (LDEDONE)**, т.е. в контексте
  принятого кадра. Прямого указания на пригодность БЕЗ кадра — **НЕ НАЙДЕНО** (привязка к
  «analysis of the accumulator data» и LDEDONE говорит об обратном).

### А3. Энергия в полосе БЕЗ кадра — есть ли регистр/режим

- **ДА, документирован — AGC energy scan.** 0x23:02 (печ.122/PDF123): *«The AGC measurement function
  might be used as an energy measurement for an "Energy Scan" as part of determining what channel to
  use.»* AGC_STAT1 EDG1/EDV2 (печ.126): *«give a measure of the background in-band noise energy level.
  This might be used for an Energy Detect (ED channel scan) as part of implementing the IEEE 802.15.4
  standard's MLME-SCAN request primitive.»* Формула Figure 27: `noise=(EDV2−40)×10^EDG1×η`.
  **Оговорка (печ.126):** *«does not give an absolute level but instead gives a **relative level**…»*
- **Просмотрено:** §4.6 (печ.43), §4.7 (печ.43–46), рег.0x12, рег.0x23 (§7.2.36), рег.0x25 ACC_MEM,
  §7.2.48.15 DIAG_TMC (только TX-тест `TX_PSTM`), Continuous Wave (только **TX** тест-режим), §4.4/§4.5.
- **Вывод А3:** единственный документированный способ получить уровень внутриполосной энергии
  независимо от кадра — **AGC-скан фона (EDG1/EDV2, 0x23:1E, DIS_AM=0)**, даёт **относительный**
  уровень. Другого «RSSI без кадра» / непрерывного измерителя мощности — **НЕ НАЙДЕНО**.

### А4. SNIFF / экономичное прослушивание

- §4.5 (печ.40/PDF41): *«Low-Power SNIFF mode is a lower power preamble hunt mode… where the receiver
  … is sequenced on and off…»* §4.1.1 (печ.32): «samples ("sniffs") the air periodically … to reduce
  the power needed during **preamble detection**». Figure 19 (печ.42): «Power profile for SNIFF where a
  frame is **not** received» — при отсутствии преамбулы просто IDLE↔RX, по таймауту → SLEEP. §4.4
  (печ.38): *«If no preamble is seen the DW1000 automatically returns to SLEEP…»*
- **Вывод А4:** SNIFF периодически включает приёмник **только для поиска преамбулы** (корреляция).
  При отсутствии преамбулы **наблюдаемого признака НЕ даёт** — уходит в idle/sleep, прерывание —
  только по принятому кадру.

### А5. КЛЮЧЕВОЕ — несовпадение кода преамбулы / PRF / длины (число модулей в макете)

- **Детект — корреляционный** (§4.1.1, печ.31): «detected by cross-correlating in chunks…».
  §9.3 (печ.209): коды «semi-orthogonal… different, preamble codes to operate simultaneously… as if
  on separate channels».
- **Несовпадение КОДА преамбулы — прямо НЕ оговорено.** Ближайшее (§10.5, печ.218/PDF219):
  *«…chosen to have a **low cross correlation** … there will be some **break-through** between
  different codes especially in conditions of close proximity with long preambles.»* Регистр RX_PCODE
  (рег.0x1F): «select the preamble code … recommended for the selected channel and PRF» — явного
  «должен совпадать с TX» для кода преамбулы (в отличие от SFD) **нет**.
- **Несовпадение PRF — НЕ НАЙДЕНО** прямого описания.
- **Несовпадение длины преамбулы (при совпад. канале)** — только косвенно через PAC (§4.1.1, Table 6,
  печ.31): *«a PAC of 64 will never receive frames with just 64 preamble symbols».*
- **Таблица каналов/кодов — Table 61 (§10.5):** каналы 1(1,2/9–12), 2(3,4/9–12), 3(5,6/9–12),
  4(7,8/17–20), 5(3,4/9–12), 7(7,8/17–20); формат «код@16МГц / код@64МГц».
- **Вывод А5:** документ **не даёт** явного правила поведения приёмника при чужом коде преамбулы
  (невозможно / с потерей чувствительности). Есть лишь «низкая кросс-корреляция + возможный
  break-through при близости/длинной преамбуле». Для PRF — молчит. Это **прямо влияет на число
  модулей** и по документу **не устанавливается** (см. НЕ УСТАНОВЛЕНО и ГИПОТЕЗЫ).

### А6. Непрерывный/нестандартный доступ к аккумулятору

- §4.1.2 (печ.32): *«Once the preamble sequence is detected, the receiver begins accumulating
  correlated preamble symbols… Accumulation stops when the SFD is detected…»* Рег.0x25 ACC_MEM
  (§7.2.38, печ.128): RO-доступ к уже накопленному CIR «for diagnostic purposes».
- **Вывод А6:** документированного режима **непрерывного/периодического** чтения аккумулятора помимо
  штатного пути (наполнение после детекта преамбулы → LDE → чтение) — **НЕ НАЙДЕНО**. Ограничение из
  6.1 `CIR_raw_capture_report` **подтверждается** (§4.1.2). Энергозамер без кадра существует, но это
  **другой тракт** (AGC EDG1/EDV2, А3), а не отсчёты аккумулятора.

## ФАКТЫ — ЧАСТЬ Б (DW3000 Family UM v1.1; QM33100 UM Rev.A как подтверждение)

### Б1. Аккумулятор CIR

- **DW3000 UM (стр.228–229):** Register file 0x15 ACC_MEM, RO, **12288 октетов**. Преамбульный CIR с
  индекса 0, **992 отсч.@16МГц / 1016@64МГц**; STS-CIR с индекса 1024, **512 отсч.**; второй STS-CIR
  (PDoA Mode 3) с индекса 1536. Отсчёт — **24-бит(3Б) Re + 24-бит(3Б) Im, реально 18-бит**, старшие
  6 бит — знак. Доступ: **1 dummy-октет** перед данными; offset — **индекс отсчёта, не байта**;
  предварительно выставить `ACC_CLK_EN`+`ACC_MCLK_EN` (0x11:04); offset>127 — indirect (PTR_A).
  Читать после `CIADONE` (стр.64). Наполняется **по детекту преамбулы** (стр.39): «Once the preamble
  sequence is detected, the receiver begins accumulating correlated preamble symbols and building a CIR».
- **QM33100 UM (стр.244–245, §4.1 стр.38, §6 стр.63)** — **подтверждает** всё вышеперечисленное
  дословно (12288 октетов, 992/1016+512, 18-бит, dummy, sample-index, ACC_CLK_EN/MCLK_EN, CIADONE).
- **Отличия от DW1000 по существу:** DW3000 строит **до 3 CIR** (1 преамбула + 2 STS; стр.178, 64),
  DW1000 — только по преамбуле; отсчёт DW3000 **18-бит (6 Б)** против DW1000. **Числового сравнения
  размера аккумулятора DW3000↔DW1000 в самих документах DW3000/QM33 — НЕ НАЙДЕНО** (дают только
  абсолютные значения DW3000). *(Для справки: DW1000 ACC_MEM — 992/1016 отсч., DW1000 UM §7.2.38.)*

### Б2. Ранний съём (до зачёта кадра / CRC)

- **События до CRC (DW3000 UM SYS_STATUS, стр.94–95):** `RXPRD` (детект преамбулы), `RXSFDD` (детект
  SFD), `RXPHD` (декод PHR завершён) — все ДО приёма данных и CRC. `RXFCG`/`RXFCE` — в конце кадра.
  Преамбульный CIR формируется на этапе накопления преамбулы (стр.39) — раньше SFD/PHR/CRC.
  Порядок подтверждён QM33 (Figure 16 стр.37; статусы стр.4990–5019).
- **НО:** оба документа предписывают **не читать ACC_MEM до `CIADONE`** (DW3000 стр.64; QM33 стр.63),
  а CIA завершается после приёма кадра; `RXFR` искусственно задержан до CIADONE (DW3000 стр.95).
- **Вывод Б2:** ранние события до CRC есть, и преамбульный CIR физически формируется до валидации —
  как на DW1000. Но **явного санкционирования чтения CIR по раннему событию (RXPRD/RXSFDD), в обход
  CIADONE, в документах НЕ НАЙДЕНО** (не разрешено и не запрещено; единственное указание — читать
  после CIADONE). Т.е. «перенос основного приёма настоящей работы» на DW3000 документами **не
  подтверждён явно** (см. ГИПОТЕЗЫ).

### Б3. Диагностика приёма; энергия БЕЗ детекта преамбулы

- **Сверх DW1000 (DW3000 стр.47–49, 178–185; QM33 стр.46–48):** `RX_POWER`/`FP_POWER` (dBm) с DGC-
  вариантом; CIA-диагностика 0x0C/0x0D/0x0E; **STS-диагностики STS_DIAG/STS1_DIAG** (новое), PDoA/TDoA,
  ToA-статус (флаги «CIR too weak», «Noise threshold artificially lowered»). QM33 добавляет **RDB_DMO**
  — 3 уровня логирования диагностики (Minimal/Medium/Full) в double-buffer (стр.6808).
- **ГЛАВНОЕ — энергия/мощность в полосе БЕЗ детекта преамбулы: НЕ НАЙДЕНО** (и DW3000, и QM33). Все
  мощностные величины считает CIA из CIR и доступны только по `CIADONE` (стр.183–184), т.е. требуют
  детекта преамбулы/STS. Более того — прямой запрет-по-физике, §5.7 Pseudo CCA (DW3000 стр.55; QM33
  стр.54): *«for UWB where this is not possible, one approach is to look for preamble… the mechanism is
  only looking for preamble…»* — исход `CCA_FAIL`, не уровень. Отдельного энергодетектора в полосе нет.
- **Просмотрено:** §4.6–4.7, §5.7, §4.5 SNIFF, §7, CIA Interface, DIAG_TMC/тест-режимы, SYS_STATUS.
- **Вывод Б3 (существенный контраст):** у **DW3000/QM33 признака энергии без преамбулы НЕ
  документировано** — в этом отношении они дают **МЕНЬШЕ**, чем DW1000 (у которого есть AGC-скан, А3).

### Б4. Покрытие конфигураций

- **Каналы (DW3000 Table 8 стр.28; QM33 Table 8 стр.27):** только **5 (6489.6 МГц)** и **9 (7987.2 МГц)**,
  полоса 499.2 МГц. Каналы **1,2,3,4,7 НЕ поддерживаются** (стр.10/9).
- **PRF:** 16 и 64 МГц. **Коды:** @16МГц — 3,4; @64МГц — 9,10,11,12 (+DPS 13–16,21–24). Поле PCODE 1–29.
- **Скорости:** **850 kb/s и 6.8 Mb/s**; **110 kb/s НЕ поддерживается**.
- **Длины преамбулы:** 16/64/1024/4096 + 128/256/512/1536/2048; «will not receive… below 32 symbols».
- **Несовпадение кода преамбулы TX/RX — прямо НЕ оговорено** (как и DW1000). Ближайшее: «low cross
  correlation… break-through… especially… long preambles» (стр.28/27); приёмник коррелирует против
  **сконфигурированного RX_PCODE** (QM33 §8.2.16 стр.244). Явной формулировки исхода — **НЕ НАЙДЕНО**.

### Б5. 802.15.4z / STS и диагностика для обнаружения

- **Поддержка (DW3000 §6 стр.62–65; QM33 §6 стр.61–64):** STS по IEEE 802.15.4z, генератор
  **AES-128 CPRNG** (128-бит key + 128-бит nonce); 3 режима размещения STS (Mode 1/2/3); длина STS
  программируется (мин.32×512 chips); **SDC** (детерминированный STS-код без управления ключами);
  PDoA Mode 1/3, TDoA между CIR.
- **Диагностика STS:** отдельный STS-CIR (ACC_MEM инд.1024+), STS_DIAG/STS1_DIAG, **ACC_QUAL** (порог
  >60% длины STS), **CP_TOAST** (статус качества ToA по STS), сравнение ToA преамбула↔STS.
- **Для обнаружения:** все STS-средства требуют **согласованного seed (ключ+nonce)** — без него
  корреляция STS плохая (стр.61–62). Механизма «слепого» обнаружения STS без ключа — **НЕ НАЙДЕНО**.
- **Вывод Б5:** 802.15.4z/STS — про **защищённую дальнометрию**, не про обнаружение без ключа.
  Диагностика STS к «слепому» детекту неприменима.

### Б6. Платформенный уровень (перенос)

- **Интерфейс:** slave-only SPI; заголовок 1–2 октета; типы — fast command / short/full addressed /
  masked write; MSB first, бит0 заголовка = R/W; режим SPI из GPIO5/6 при reset или из OTP; опц.
  **SPI-CRC** (CRC-8-ATM).
- **Предельная частота SPI:** **до 38 МГц** в IDLE_PLL (DW3000 стр.19; QM33 стр.18); **7 МГц** в
  IDLE_RC; **20 МГц** при включённом SPI-CRC. (QM33 маркетинг-строка «up to 32 MHz», §1.1 стр.6 —
  расхождение с 38 МГц по состояниям; точные тайминги — datasheet, отсутствует → НЕ УСТАНОВЛЕНО.)
- **Инициализация:** POR → INIT_RC → восстановление из AON/OTP → IDLE_RC → хост ставит `AINIT2IDLE`
  → CLKPLL lock → IDLE_PLL; ждать прерывание **SPIRDY** перед SPI; перед первым RX — **RX-калибровка**
  `dwt_pgf_cal()` (авто при wakeup если ONW_PGFCAL; рекалибровка при ΔT=20°C). XTAL 38.4 МГц.
- **Драйвер/API:** официальный **DW3000/QM33 device driver** в исходниках (ARM Cortex-M, [3]); API —
  **то же семейство `dwt_*`** (dwt_initialise, dwt_pgf_cal, dwt_otpread), НО **регистровый интерфейс
  иной, чем у DW1000** → *«modified software is needed since the … control register interface is
  different to that of the DW1000»* (DW3000 стр.10; QM33 стр.9). Это **отдельный драйвер поколения
  DW3000**, не наш DW1000-DecaDriver, хотя стиль API совпадает.
- **DEV_ID:** DW3000 UM конкретного значения не даёт (→ datasheet, НЕ УСТАНОВЛЕНО); QM33 —
  `0xDECA0304/0314` (для семейства QM33, не DW3000-как-такового).

## ГИПОТЕЗЫ (вывод из документов, не прямые утверждения)

1. **ГИПОТЕЗА (число модулей / несовпадение кода).** Т.к. детект преамбулы — корреляция против
   *сконфигурированного* кода RX, а коды имеют «low cross correlation» (А5; Б4), приёмник, настроенный
   на код X, **скорее всего не детектирует надёжно чужой код Y** (кроме близкого «break-through»).
   *Шаг вывода:* «корреляционный детект + низкая кросс-корреляция» ⇒ «чужой код не детектируется».
   Документы этого прямо не утверждают ⇒ гипотеза. Следствие: для покрытия всех кодов/PRF/каналов нужен
   отдельный модуль (или реконфигурация) на комбинацию — **точное число модулей по документам не
   выводится**, нужен замер.
2. **ГИПОТЕЗА (AGC как грубый «есть энергия»).** AGC-скан DW1000 (EDG1/EDV2, А3) можно использовать как
   **грубый относительный индикатор «энергия в полосе»** без преамбулы. *Шаг вывода:* документ описывает
   его для «Energy Scan/ED channel scan», но НЕ как непрерывный детектор присутствия; пригодность как
   детектора (порог, скважность при 32 µs settle + DIS_AM-тоггл, только относительный уровень) — вывод,
   не утверждение. Требует проверки на железе.
3. **ГИПОТЕЗА (ранний съём на DW3000).** Раз преамбульный CIR формируется до CRC (Б2), «ранний съём» по
   RXPRD/RXSFDD **физически возможен** и на DW3000 (как на DW1000). *Шаг вывода:* «CIR есть до CRC» ⇒
   «его можно прочитать до CIADONE». Документ этого не санкционирует (предписывает читать после CIADONE)
   ⇒ гипотеза, требует эксперимента.

## НЕ УСТАНОВЛЕНО (с перечнем просмотренного)

1. **Поведение приёмника при несовпадении КОДА преамбулы** (невозможно / потеря чувствительности) —
   ни в одном из трёх документов. Просмотрено: DW1000 §10.5/§9.3/§4.1.1/RX_PCODE(0x1F); DW3000 §2.6/
   CHAN_CTRL/§4.1.1; QM33 §2.7/§8.2.2.27/§8.2.16. Есть только «low cross correlation / break-through».
2. **Поведение при несовпадении PRF** (DW1000) — НЕ НАЙДЕНО (§7.2.32 RXPRF описывает только выбор поля).
3. **Числовое сравнение размера/разрядности аккумулятора DW3000↔DW1000** — DW3000/QM33 дают только
   абсолютные значения. Просмотрено: DW3000 §2.2/§6/рег.0x15; QM33 §2.2/§8.2.16.
4. **Точные тайминги SPI и значение DEV_ID DW3000** — отсылка к datasheet [5], которого в репозитории
   нет (STOP-условие). По UM: только «до 38 МГц / 7 / 20 с CRC» (состояния), значение DEV_ID DW3000 не
   приведено (QM33 даёт свой `0xDECA03xx`).
5. **Санкционированный ранний доступ к ACC_MEM до CIADONE** (DW3000/QM33) — НЕ НАЙДЕНО (только запрет
   читать до CIADONE). Просмотрено: DW3000 §4.1/§6/SYS_STATUS/рег.0x15; QM33 §4.1/§6/§8.2.16.

## ЧТО ЭТО МЕНЯЕТ для состава макета (коротко, только где факты меняют записанное ранее)

1. **Уточнение к выводу 6.1 `CIR_raw_capture_report`.** «Эфир без сигнала через DW1000 не наблюдаем»
   верно **для аккумулятора/CIR** (подтверждено, А6), но **не абсолютно**: у DW1000 есть отдельный
   **AGC-энергозамер фона без преамбулы** (EDG1/EDV2, А3) — относительный, грубый, для ED-скана. Это
   **кандидат на грубый гейт «есть энергия в полосе»** до/вместо преамбульного захвата. Оценить на
   железе (гипотеза 2).
2. **Переход на DW3000/QM33 НЕ даёт «слепого» энергодетектора.** Ключевой контраст (Б3): у DW3000/QM33
   признака энергии без преамбулы **не документировано вовсе**, а §5.7 прямо говорит, что для UWB это
   «not possible» кроме поиска преамбулы. Т.е. для задачи *обнаружения без декодирования* DW3000 в этом
   отношении **не сильнее** DW1000 (даже слабее — нет AGC-скана в UM). Преимущества DW3000 — STS/802.15.4z
   (защищённая дальнометрия) и канал 9, а НЕ обнаружение. Это меняет мотивацию выбора чипа для
   детектора: если цель — обнаружение, DW3000 сам по себе проблему не решает.
3. **Число модулей в макете по документам не выводится.** Поведение при чужом коде преамбулы не
   оговорено ни одним UM (п.1 НЕ УСТАНОВЛЕНО). Сколько конфигураций (канал × PRF × код × длина) покрывает
   один модуль — **вопрос замера**, не документа. Оценку числа модулей 5-канального макета нельзя
   обосновать ссылкой на UM; нужен эксперимент по кросс-детекту.
4. **Каналы.** DW1000 покрывает больше legacy-каналов (1,2,3,4,5,7), DW3000/QM33 — только 5 и 9. Для
   «слышать разный UWB» это в пользу DW1000 по legacy-каналам; нативный PHY DW3000 (STS/4z) — иной
   тракт, вне сравнения по обнаружению.
